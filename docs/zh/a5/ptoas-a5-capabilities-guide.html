三种“并行”要分别看

多核 block 划分是核之间的并行；MTE / Vector / Cube 是流水线并行；SIMT lane 是 Vector 侧的线程执行语义。一个 launch 里的多 AIV 不自动生成 warp 操作。

SIMD 与 SIMT 共享 Vector 侧资源

在一个内核中可以组合两种形式，但切换、依赖与资源占用必须被编译器和程序正确建模。不能从“两种 API 都存在”推导二者可任意同时执行。

一个内核中的物理 section

valid shape 与物理 shape 各管什么

物理 shape

决定本地缓冲容量和布局。尾块即使只剩少量有效元素，仍可能占完整 Tile 存储。

valid shape

描述当前有效行列。需要 op、mask 和搬运路径共同遵守；不能只修改 shape 就推导所有物理读取都被裁剪。

VPTO 下 TileOp expansion 由 --pto-backend=vpto 驱动；旧的 --enable-tile-op-expand 是兼容开关。TileLib 模板选择、隐式 tmp 物化、section 边界与目标 verifier 共同决定一个 Tile 算子如何进入 micro 层。

选择策略：先用 Tile 表达能覆盖的计算；当需要逻辑向量控制时使用 VMI；当热点涉及特殊访存 / 寄存器 / 配置时再下降到 micro。每次下降一层，都需要承担更多布局、mask 与同步责任。

07 / LOGICAL TO PHYSICAL LAYOUT

VMI：一个逻辑向量怎样落到寄存器

VMI 让用户按逻辑元素写程序；PTOAS 负责记录每个元素最终在哪个物理寄存器、哪个 lane。转换与重排后的布局会沿消费者传播，直到必须物化的边界。

A5 物理向量寄存器：256 B = 2048 bit 每寄存器元素数 E = 2048 / bitwidth(T) 逻辑向量物理寄存器数 K = ceil(L × bitwidth(T) / 2048) 示例：256×f32 → 4 regs；256×f16 → 2 regs；256×i8 → 1 reg

交互为数学布局示意，parity 展示要求至少两个物理寄存器；不代表某个类型的所有 op 都可要求该布局。内部布局由 lowering 管理，公共 PTODSL 类型接口不直接选择 layout。

跟踪一次 f16 → f32 扩宽

读入 V<128×f16>

逻辑 128 个元素，占一个 256B 物理寄存器。

扩宽为 V<128×f32>

需要两个 256B 寄存器；物理 vcvt 可以分别处理 EVEN 与 ODD part，输出自然形成偶 / 奇分离。

逐元素计算继续沿用布局

只要两个输入的 lane 语义兼容，elementwise 运算可以在这一布局上继续，不必立刻插入交织。

存回逻辑连续结果

边界可以使用 vstsx2 INTLV_B32，或按后续要求物化连续布局。实际输出需检查生成 IR、对齐与访问范围。

三项容易遗漏的限制

  • 公共 logical lane 数为 1/2/4/8/64/128/256。内部 lowering 接受的额外正整数长度不自动成为公共 PTODSL 合同。
  • 小向量仍占至少一个物理寄存器；未定义的 padding lanes 必须按 op 合同屏蔽。
  • VMI load 的物理 footprint 不能仅用消费者 mask 推断安全；地址分析、dist 与 load 的实际读取范围需要一起检查。复杂访存重构的设计目标与当前实现要区分。

2026-10-30 补充 · VMI 负责什么，访存还要明确什么

VMI（Virtual Micro-instruction，虚拟微指令）面向逻辑 SIMD 向量。编译器负责逻辑向量的物理拆分与布局；用户仍需表达加载、计算和存储。GM↔UB、UB↔L1 等存储间搬运及其完成依赖由 Tile / micro 与同步接口组织。

pto.vecscope() 是无参数的代码区域，可使用外层变量；它本身没有 ptr / Tile 参数约定。外层函数的参数由入口或 helper 类型决定。pto.vmi.vload 当前接受 ptr 或 memref 源，不直接接受 Tile；持有 UB Tile 时先用 tile.as_ptr() 取得指针。

# 片段示意：tile 是连续行主序的 UB f32 Tile，shape 为 4×128；
# 数据已搬入，起始地址满足访存对齐要求，每行有 128 个可读元素。
p = tile.as_ptr()
row0 = pto.vmi.vload(p,   0, size=128)
row1 = pto.vmi.vload(p, 128, size=128)

上述两次加载的结果都是 V<128×f32>：元素类型来自指针，逻辑 lane 数来自 size；offset 的单位是元素。若每行存在 padding 或非连续布局，必须按实际行步长和支持的访问模式表达，不能直接套用此偏移。

信息由谁提供 / 需要遵守的条件
Tile shape / valid shape描述缓冲的组织与有效区域；转成指针后，不会自动变成本次加载的长度或 mask。
逻辑向量长度通过编译时的 size 指定，公共值为 1/2/4/8/64/128/256；由编译器拆成所需物理寄存器。
动态访问起点vload(p, pos, size=128) 可以表达运行时偏移；具体类型与访问方式仍须满足对齐、实际可读范围等条件。支持动态地址不等于能精确证明所有地址间的关系。
动态有效 lanelane < n 的 mask 控制支持掩码的计算或存储；它不改变此前 vload 的起点，也不会自动缩短加载的读取范围。
实际访存范围小向量、跨步与特殊访存应按实际访问方式检查；逻辑 payload 字节数不总等于物理读取范围。原始 ptr 本身没有完整分配容量信息。

地址对齐、访问不越界、访问之间的重叠和先后顺序是分别需要满足的条件。屏障只能约束顺序，不能修复越界或错误布局。UB 重叠分析与默认同步的限制见第 13 节补充。

为什么调度不能“随便换顺序”

DAG 除 SSA 数据依赖，还要包含内存 alias 的 RAW / WAR / WAW、隐式配置状态与同步依赖。循环、调用或其他边界限制调度区间；不认识的节点要保守保序。合法性检查完成后才应用新顺序。

32 与 7：模型阈值，不是全部硬件资源的描述

当前 scheduler 以 vector=32、predicate=7 计算 SSA 压力，predicate 依据后端使用的 P1–P7 校准。predicate 超限不会单独触发 vector remat。重物化受前驱深度、代码膨胀和压力集合预算约束；若二次调度失败、vector 峰值未下降，或最终有上限的压力集仍超限，会回滚克隆、use 替换与首次调度顺序。

报告不能当作硬件周期：当前 generic-a5-v4 模型中的 resource / hazard 字段仍含占位 mock 值，调度和重放不据此推进真实机器周期。analyze 有助于定位依赖与压力，不等同硬件性能预测；收益需用目标工具链、simulator 和真机测量。

其他专用机制参考稿记录 AIPP 改软仿，以及边界设定、UB 调试、repeat 最值/索引读取接口变化。依赖这些功能的内核应逐项确认替代路径；本次未核查其在 PTOAS 中的完整迁移实现。
上层框架覆盖须单独核查：整理稿的 PyPTO 状态对应 2026-10-21 的独立版本，既不能限定 PTOAS 本身的能力，也不能由 PTOAS 存在某个接口推导 PyPTO 已接入。这里聚焦 PTOAS，不把该历史快照写成 PyPTO 的当前支持承诺。
